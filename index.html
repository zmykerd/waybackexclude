    How it works
      

    1. Publish robots.txt at the root of each domain so it loads at https://your-domain/robots.txt. This works on any host: your own server, a CMS, shared hosting, GitHub Pages, DuckDNS and so on. It stops future crawls but does not delete what is already archived.
      2. 

    2. Send the drafted email to info@archive.org from an address tied to the site. It names the URLs, the scope, and when you controlled the site.
      3. 

    3. Wait for a reply. The Archive publishes no turnaround time; expect days to a few weeks.
      4. 

    4. Use the check links under the output. Removed URLs show an exclusion notice instead of snapshots.
    

    Good to know
      

    • Only send requests for sites you own or administer, and keep the proof field specific; the Archive may ask for it.
      • 

    • robots.txt compliance is voluntary and does not remove existing captures. The email does.
      • 

    • Date-range and file-type removals are email-only, since robots.txt cannot be scoped by date.
      • 

    • Keep the robots.txt online after the removal if you want the exclusion to hold.
      • 

    • Each subdomain serves its own robots.txt, so list and publish one per subdomain.
      • 

    • The domains and contacts are written into robots.txt as comments, and that file is public. Use a role address if you do not want scrapers to see yours.
    

    Review the draft before sending it. Wayback Exit only builds text.
